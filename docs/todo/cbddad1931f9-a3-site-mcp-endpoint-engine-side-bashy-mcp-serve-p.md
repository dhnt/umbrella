Design: docs/agent-ready-sites.md Layer 2 (MCP), reworked 2026-11-23 on operator direction: the MCP endpoint is <origin>/mcp on the SAME origin as the pages, served by the same front (hosted plane for dhnt.io; the outpost app for a companion site) as a reverse proxy to bashy mcp serve --transport http on the owner's engine, exactly as the pages are proxied today; no redirect to another host (that would drop the cookie and the relationship stamp). MCP Streamable HTTP is POST plus an SSE GET on one path, so it rides the existing proxy and the existing session: the caller is the same principal the pages see (anonymous, signed-in, member, owner from the session cookie or the signed stamp) and the tool set follows the same tiers (anonymous: read tools only if the owner allows; members: what their audience admits; owner: the shape tools). For clients that cannot carry the site cookie, /.well-known/oauth-protected-resource points at the site's own sign-in, which is the OAuth flow, so authorizing the MCP client and logging in are one step. Behind the proxy, bashy mcp serve gains a 'site' tool profile backed by the site module: list_pages, read_page(path|url, format), cite(url#id) returning the citation record, and shape wish/verify/preview/approve/undo through the existing shape service, gated by the proxied principal. The endpoint and the server card (/.well-known/mcp/server-card.json) are generated by the template from site.json. Split: A3 engine side (bashy/yoke profile + outpost app proxy + template) and the hosted-plane proxy for dhnt.io (same auth middleware as the pages). Acceptance: Claude Code (claude mcp add --transport http), Codex, Gemini CLI and OpenCode connect to <origin>/mcp from the URL in the agent block and call read_page and cite; a signed-in owner shapes through MCP; a member or anonymous caller is refused by name with the pages' tier rules; the engine behind the proxy is the owner's.
